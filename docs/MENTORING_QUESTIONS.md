# 멘토링 질문 리스트

프로젝트를 진행하며 우리끼리 경험적으로 판단했거나, 확신 없이 가정하고 넘어간 지점들을 모았다.
각 질문에 "왜 이게 궁금한지" 맥락을 같이 적어, 멘토가 배경 설명 없이 바로 답할 수 있게 한다.

---

## A. 도메인(화학 공정/TEP) 관련

1. **현재 AE + run-level 집계로 F1 0.92를 달성했는데, TEP 벤치마크 기존 연구 대비 어느 수준인가?**
   Hartung 2023(arXiv:2303.05904)에서 재구성 오차 기반 딥러닝이 상위권을 차지한다는 것만 알고
   있는데, 우리의 0.92가 경쟁력 있는 수치인지, 아니면 아직 갭이 큰지 가늠이 안 된다.
   (경로 요약: row-level IF 0.58 → run-level IF 0.87 → AE 0.92)

2. **train 데이터(500개 run)가 정상 운전의 모든 영역을 대표한다고 가정해도 되는가?**
   실제 공정에는 생산 grade 변경 등으로 여러 "정상 모드"가 존재한다는 이야기를 들었다. 만약
   다중 정상 모드가 있다면 AE가 일부 정상 패턴을 복원하지 못해 오탐이 생길 수 있는데, TEP
   시뮬레이션에서 이것이 실제로 문제가 되는 케이스인지 궁금하다.

---

## B. 검증 방법론

3. **train이 100% 정상이라 로컬에서 recall을 측정할 방법이 없어, 13번의 실험을 전부 리더보드
   제출에 의존했다.** 이런 구조(novelty detection, 정상만 있는 train)에서 표준적으로 쓰는 로컬
   검증 기법이 있는지 궁금하다. 예를 들어 synthetic fault injection처럼 정상 데이터에 인위적
   변형을 가해 가짜 이상치를 만드는 방법이 실제로 쓰이는지, 그게 TEP 같은 공정 데이터에도
   유효한지 알고 싶다.

4. **RUN_CONTAMINATION(run 중 이상으로 판정할 비율)을 "추정 실제 anomaly 비율 ≈ 32%"에 맞춰
   설정하고 있는데, 이것이 최선인가?**
   현재 방식: F1 + Accuracy + 예측 positive 수로 confusion matrix를 역산해 실제 비율을 추정하고
   그 값으로 threshold를 맞춘다. 직관적이지만 F1 자체를 쫓는 circular한 면이 있다. 재구성 오차
   분포를 직접 시각화해서(정상 train 오차 vs test 오차 히스토그램) threshold를 잡는 방식이
   더 나은지, 아니면 이 추정 방식이 충분히 합리적인지 궁금하다.

5. **F1 + Accuracy + 예측 positive 수 세 값으로 confusion matrix(TP/FP/FN/TN)를 완전히
   역산하는 기법을 13번의 실험 내내 써왔다.** 수학적으로는 맞고 검산도 소수점 4자리까지 일치했다.
   다만 F1/Accuracy가 소수점 4자리 반올림이라 추정값에 수백 row 수준의 오차가 있을 수 있는데,
   이 기법이 학습/연구/실무에서 실제로 사용되는 방법인지, 그리고 정확도 한계를 어떻게 보정하는지
   알고 싶다.

## C. 모델링/구조 관련

6. **TEP에서 simulationRun 단위로 라벨이 통째로 0 또는 1이기 때문에, row 단위 판정 대신
   run 단위 집계(row별 이상 점수 → run별 평균 → threshold)를 선택했다(Exp 8). IF F1이
   row-level 0.59에서 run-level 0.87로 뛰었고, AE도 같은 방식으로 0.92를 달성했다.**
   이 접근이 FDC(Fault Detection and Classification) 분야 문헌에서도 표준적인 방법인지
   궁금하다. 또는 timestep 단위 라벨 예측 후 run 단위로 majority vote 하는 방식이 더 일반적인지.

7. **AE가 IF보다 F1이 높아진 것(0.87 → 0.92)이 AE의 재구성 오차 방식 덕분인지,
   아니면 StandardScaler 전처리 덕분인지 분리하지 않았다.**
   IF는 이론상 스케일 불변이라 StandardScaler를 적용하지 않았고, AE에는 StandardScaler를
   추가했다. 즉 두 모델을 바꾸면서 전처리도 같이 바뀌어 원인이 섞였다. IF + StandardScaler를
   실험하면 AE와의 비교가 더 공정해지는데, 이게 실험적으로 의미 있는 시도인지, 아니면
   IF의 스케일 불변성으로 인해 결과가 의미없을지 궁금하다.

8. **AE 구조에서 bottleneck 크기를 52 → 8로 설정했는데(약 6.5배 압축), 이 값을 정하는
   원칙이 있는가?**
   현재는 "충분히 좁아서 정상 패턴 압축을 강제한다"는 직관으로 8을 골랐다. xmeas_12↔xmv_7
   같은 완전 상관 쌍이 있으면 유효 차원이 52보다 훨씬 낮을 수 있는데, 그렇다면 bottleneck을
   더 좁혀야(4 이하) 이상 탐지 분리력이 더 높아지는지, 아니면 너무 좁으면 정상 패턴도
   복원 못해 오탐이 늘어나는지, 일반적인 경험칙이 있다면 알고 싶다.

9. **실험을 설계할 때 "한 번에 하나씩만 바꾼다"는 원칙으로 진행했다.** 이게 ML 실험 방법론
   관점에서 올바른 접근인지, 아니면 ablation study나 grid search처럼 여러 조합을 한 번에
   비교하는 방식이 실무/대회에서 더 많이 쓰이는지 궁금하다. Exp 12에서 n_estimators와
   RUN_CONTAMINATION을 동시에 바꾼 적이 있어 어느 쪽 기여인지 분리하지 못한 케이스가 있었다.

10. **모델 교체 시점을 어떻게 판단해야 하는가?**
    이번 프로젝트에서 두 가지 상반된 경험을 했다.
    - OC-SVM으로 교체(Exp 5): F1 0.38로 폭락 → **잘못된 교체**
    - AE로 교체(Exp 13): F1 0.87 → 0.92 → **옳은 교체**
    전자는 "구조적 한계를 오해한 교체"였고 후자는 "명분 있는 교체"였는데, 사전에 이 둘을
    구별하는 기준이 있는지, 아니면 결국 실험 후에야 알 수 있는 것인지 궁금하다.

11. **SGDOneClassSVM을 row-level로 실험했을 때 F1이 0.38이었다(Exp 5~7). 이후 IF에
    run-level 집계를 적용하니 F1이 0.87로 급등했다(Exp 8). run-level 집계를 OC-SVM에도
    적용했다면 결과가 달랐을까?**
    "선형 커널이라 근본적으로 한계가 있다"고 판단해 시도하지 않았다. 그런데 row-level 점수
    품질이 낮더라도 960개 row의 평균을 냈을 때 정상/이상 run이 분리될 가능성이 있는지,
    그리고 그 가능성을 사전에 판단하는 방법(예: row-level score 분포를 run별로 시각화)이
    있는지 궁금하다.

## 멘토링 답변 요약 (2026-07-02)

아래는 멘토링 세션에서 받은 답변을 질문 번호별로 정리한 것이다.

**Q3 (로컬 검증)**: Synthetic fault injection은 실제로 쓰이는 방법이지만, TEP 같은 공정 데이터에는
비추천. 이유: 화학 공정은 센서 간 물리 관계(반응식, 열역학)가 복잡하게 얽혀 있어, 인위적으로
만든 이상치가 실제 공정 고장과 다른 패턴을 가질 가능성이 높다. 결국 리더보드 제출이 현실적인
유일한 검증 수단이다.

**Q4 (RUN_CONTAMINATION 설정)**: F1 역산으로 추정한 비율에 threshold를 맞추는 현재 방식은
circular하다. 더 나은 방법은 train의 이상 점수 분포와 test의 이상 점수 분포를 히스토그램으로
직접 시각화한 후, 두 분포 사이의 자연스러운 "골짜기"에 threshold를 설정하는 것이다.

**Q6 (run-level 집계가 표준인지)**: run-level 집계 자체가 성능 도약의 원인이 맞다. t-SNE는
그 방향을 발견하게 해준 시각화 도구일 뿐이고, 실제 효과는 집계 방식의 변화에서 나온 것이다.
t-SNE를 사용하지 않았더라도 run-level 집계를 처음부터 적용했다면 같은 결과가 나왔을 것이다.
FDC 문헌에서는 run 단위 판정이 표준적인 접근이다 (라벨이 run 단위일 때).

**Q8 (AE bottleneck 크기)**: **8은 너무 작다.** 일반적으로 256이나 128에서 시작해 16 정도까지
줄여가며 탐색한다. 52개 피처 기준으로 유효 차원이 낮더라도, 너무 좁은 bottleneck은 정상 패턴도
복원하지 못해 전체 재구성 오차가 높아지고 정상/이상 분리력이 오히려 떨어진다. 현재 AE(bottleneck=8)
의 성능 개선 여지가 있다는 의미이기도 하다.
