## Exp 1 — contamination 0.32 (`'auto'` → 0.32)

**날짜**: 2026-06-30

**재현 커밋**: `d2327fe` — `cd src && python run_experiment.py` (EXP_NAME="exp1", CONTAMINATION=0.32)

**변경 사항**: Exp 0과 모든 게 동일, `IsolationForest`의 `contamination`만 `'auto'` → `0.32`로
변경. 가설: train 기준 threshold를 풀어주면 test에서 더 많이 "이상"으로 잡아 recall이 오를 것이다
(Exp 0 분석의 직접적인 후속).

**로컬 진단 (제출 전)**: predicted positive rate가 14.81% → **44.36%**로 상승 — 목표였던 32.2%를
12%p 초과. `contamination`이 train(100% 정상) 점수 분포 기준 threshold이기 때문에, 그 threshold를
test에 적용했을 때 정확히 같은 비율이 나온다는 보장이 없다는 점(Q&A 기록 참고)이 그대로 드러남.
test 점수 분포가 train보다 더 넓게 퍼져 있다는 뜻이며, 두 가지 가능성을 구분해야 함:
1. test의 실제 이상 run들이 점수를 크게 끌어내림 (recall이 크게 오르는 좋은 신호)
2. test의 정상 run도 train 정상과 미세하게 달라 threshold에 과민 반응 (precision이 크게 깎이는
   나쁜 신호)

**점수 (public)**: F1 0.5699, Accuracy 0.6704

**Confusion matrix 역산** (Exp 0와 동일한 방법, PP=315,112):

| | Exp 0 (`auto`) | Exp 1 (`0.32`) |
|---|---|---|
| TP | 93,573 | 155,128 |
| FP | 11,631 | 159,984 |
| FN | 134,996 | 74,164 |
| TN | 470,200 | 321,124 |
| Recall | 0.4094 | 0.6766 |
| Precision | 0.8894 | 0.4923 |
| F1 | 0.5607 | 0.5699 |
| Accuracy | 0.7936 | 0.6704 |
| 추정 실제 anomaly 비율 | 0.3217 | 0.3228 (두 실험이 독립적으로 거의 같은 추정치를 줌 — 신뢰도 ↑) |

**분석**:
1. **threshold 위치가 핵심 병목이 아니었다.** FP가 11,631 → 159,984로 13배 넘게 폭증하고 recall이
   41%→68%로 크게 올랐는데도 F1은 +0.0092밖에 안 올랐다 — recall/precision이 거의 1:1로 상쇄되며
   F1 곡선이 이 구간에서 평평하다는 뜻.
2. **모델의 anomaly score 자체의 분리력이 약하다는 신호.** predicted positive rate(44.36%)가 이미
   추정 실제 비율(32.3%)을 넘어섰는데도 recall이 67.66%에 그쳤다 — score가 정상/이상을 잘
   구분했다면 실제 비율 근처로 threshold를 맞췄을 때 recall이 100%에 가까워야 한다. 그렇지 않다는
   건 새로 잡힌 FP 다수가 진짜 이상이 아니라 그냥 threshold 근처의 애매한 정상 데이터라는 뜻 —
   Exp 0에서 보류했던 가설 2번(row 독립 가정의 한계, 시간 정보 미사용)이 이 결과로 뒷받침됨.
3. 결론: Tier 1(threshold 튜닝)만으로는 한계에 가까워 보인다. 한 지점(0.32)만으로 단정하기엔
   이르지만, recall/precision이 거의 대칭적으로 상쇄된 점이 강한 신호.

## Exp 2 — contamination 0.23 (Exp 1 결과로부터 외삽)

**날짜**: 2026-06-30

**변경 사항**: Exp 1의 predicted positive rate(44.36%)가 목표(32.2%)를 1.39배 초과했으므로,
`0.32 / 1.39 ≈ 0.23`으로 거칠게 외삽해 다음 값을 잡았다. Tier 1(threshold 튜닝)이 한계에
부딪혔는지, 아니면 아직 더 나은 지점이 남아있는지(F1 곡선의 모양)를 확인하기 위한 세 번째 점.

**로컬 진단 (제출 전)**: predicted positive rate 36.13% — 목표(32.2%)와의 오차가 Exp 1(12%p)보다
줄어든 4%p. 외삽 방향은 맞았지만 여전히 정확히 일치하지는 않아 contamination↔test rate 관계가
완전한 선형은 아님을 다시 확인.

**점수 (public)**: F1 0.5812, Accuracy 0.7133 — **지금까지 최고 F1**

**Confusion matrix 역산** (PP=256,696): TP=141,325, FP=115,371, FN=88,301, TN=365,403 →
Recall 0.6155, Precision 0.5506, 추정 실제 anomaly 비율 0.3232 (Exp 0/1과 거의 동일, 재확인됨)

**Exp 0/1/2 종합 비교**:

| | predicted rate | F1 | recall | precision |
|---|---|---|---|---|
| Exp 0 (`auto`) | 14.81% | 0.5607 | 0.4094 | 0.8894 |
| Exp 1 (`0.32`) | 44.36% | 0.5699 | 0.6766 | 0.4923 |
| Exp 2 (`0.23`) | 36.13% | **0.5812** | 0.6155 | 0.5506 |

**분석**:
1. **F1이 역U자(봉우리) 모양** — predicted rate가 추정 실제 비율(32.3%)에 가장 가까운 Exp 2가 F1
   최고점. "predicted rate ≈ true rate" 휴리스틱이 실제로 유효했음이 확인됨.
2. 그러나 봉우리의 **높이 자체가 0.58 부근에 머물러 있다.** 거의 정확한 threshold(Exp 2)에서도
   recall 61.55%/precision 55.06%로 둘 다 평범 — threshold를 더 정밀하게 맞춰도 추가로 얻을 수
   있는 F1은 크지 않을 것으로 추정됨 (이미 봉우리 근처).
3. Exp 1에서 제기했던 가설(row 단위 anomaly score의 분리력 자체가 약함)이 다시 뒷받침됨 — Tier 1
   (threshold 튜닝)은 거의 소진된 것으로 판단, Tier 2(시간 정보 feature)로 넘어갈 근거가 충분함.

## Exp 3 — diff feature 추가 (원본 52개 → 원본 + 변화량 = 104개)

**날짜**: 2026-07-01

**재현 커밋**: Exp 3 코드(run_experiment.py)는 결과 확인 후 Exp 4로 바로 수정돼 별도 커밋 없음.
`preprocess.py`의 `add_diff_features` 함수는 Exp 4 커밋에 포함됨. Exp 3를 재현하려면
`select_features` 대신 `pd.concat([select_features, add_diff_features], axis=1)` 사용.

**변경 사항**: Exp 2와 모든 게 동일. feature만 변경.
- **기존(Exp 0~2)**: 센서 52개의 현재 값만 입력 → 모델이 "지금 이 순간 값들이 이상한가?"만 판단
- **Exp 3**: 현재 값 52개 + 직전 시점 대비 변화량 52개 = 104개 입력 → "지금 이상한가?" + "지금 빠르게 변하고 있는가?"를 동시에 판단

**왜 diff를 추가했나**: 화학공정 고장은 순간적으로 폭발하는 게 아니라 서서히 시작된다. 고장 초반 몇 분은 각 시점의 센서 값을 따로 떼어보면 정상 범위 안에 있어서 모델이 못 잡는다. 그러나 값이 "지금 얼마나 빠르게 올라가고 있는가(변화량)"를 함께 보면 조기에 감지할 수 있다는 가설이다. Exp 0~2에서 threshold를 아무리 정밀하게 조정해도 F1이 0.58에서 막힌 이유가 "정보 자체의 부재"라고 판단해 Tier 2(feature 추가)로 전환했다.

**왜 rolling(평균/표준편차)이 아니라 diff를 먼저 선택했나**: rolling은 "몇 개의 이전 시점을 볼 것인가(window 크기)"라는 새 하이퍼파라미터가 생긴다. 그 값을 10으로 잡든 50으로 잡든 근거가 없어서 "feature 효과"와 "window 크기 효과"가 뒤섞인다. diff는 하이퍼파라미터가 전혀 없고 "직전 대비 변화량"이라는 의미가 명확하다 — 효과 여부를 깔끔하게 검증할 수 있는 가장 단순한 방법이라 먼저 택했다.

**diff 설계 시 지킨 두 가지 규칙**:
1. `simulationRun`별로 묶어서 변화량을 계산한다. 실험 A의 마지막 시점과 실험 B의 첫 시점을 빼면 물리적으로 의미 없는 큰 값이 나오기 때문이다.
2. 각 실험의 첫 시점은 "직전 값"이 없어서 변화량이 정의되지 않는다(NaN). 이 행을 제거하면 제출 파일이 710,400행이 안 되어 채점이 깨진다 — 0으로 채운다(첫 시점은 변화 없음으로 간주).

**로컬 진단 (제출 전)**:

| | Exp 2 (기준) | Exp 3 |
|---|---|---|
| contamination | 0.23 | 0.23 (동일) |
| 입력 feature 수 | 52개 | 104개 |
| 예측 positive 수 | 256,696 | 249,321 |
| 예측 positive 비율 | 36.13% | 35.10% |
| 추정 실제 비율 | 32.20% | 32.20% |
| 비율 오차 | 4.1%p | **2.9%p** |

같은 threshold인데 모델이 "이상"이라고 판단한 행이 7,375개 줄었다. diff feature를 추가함으로써 모델이 추가 정보(변화량)를 활용해 일부 애매한 행을 "변화량은 정상이네" 하고 정상으로 돌려보낸 것으로 해석된다. 예측 비율이 실제 추정치에 2%p 더 가까워졌다 — 좋은 신호이나 F1 향상 여부는 제출 결과로만 확인 가능하다.

**점수 (public)**: F1 0.5611, Accuracy 0.7041 — Exp 2(0.5812)보다 낮고 Exp 0(0.5607)과 거의 동일

**Confusion matrix 역산** (PP=249,321):
FP+FN = 710,400 × (1-0.7041) ≈ 210,198 → TP ≈ 134,379

| | 예측 정상 | 예측 이상 |
|---|---|---|
| 실제 정상 | TN ≈ 365,823 | FP ≈ 114,942 |
| 실제 이상 | FN ≈ 95,256 | TP ≈ 134,379 |

Recall ≈ 0.5852, Precision ≈ 0.5390 (추정 실제 anomaly 비율 ≈ 0.3232, Exp 0~2와 동일)

**Exp 2 vs Exp 3 비교**:

| | Exp 2 | Exp 3 | 변화 |
|---|---|---|---|
| Recall | 0.6155 | 0.5852 | ↓ 악화 |
| Precision | 0.5506 | 0.5390 | ↓ 악화 |
| F1 | 0.5812 | 0.5611 | ↓ 악화 |

**분석 (음수 결과 — 이것 자체가 중요한 정보)**:

정밀도와 재현율이 둘 다 내려갔다. 하나가 오르고 하나가 내리는 tradeoff가 아니라 양쪽 모두 악화됐다는 건, diff feature 추가가 모델의 판단 능력 자체를 떨어뜨렸다는 뜻이다.

원인 후보 세 가지:
1. **차원 증가가 IsolationForest에 독이 됐다.** IF는 랜덤하게 feature를 선택해 분기하는데, 52개 → 104개로 늘어나면 유용한 feature가 선택될 확률이 절반으로 줄어든다. diff feature들이 "노이즈 차원"처럼 작용해 판단을 흐렸을 가능성이 높다.
2. **단 한 시점의 변화량은 정상 상태에서도 너무 시끄럽다(noisy).** 센서 값은 정상 운전 중에도 매 시점 미세하게 흔들리므로, diff의 대부분이 고장 드리프트가 아닌 배경 노이즈다.
3. **이 데이터의 고장 유형이 점진적 드리프트보다 step-change(순간 폭발적 변화) 위주일 수 있다.** Step-change 고장은 이미 절댓값에서 잘 보이므로 diff가 추가 정보를 거의 못 준다.

**결론**: `diff feature + IsolationForest` 조합은 효과 없음을 확인. "시간 정보가 부족하다"는 원래 가설은 맞을 수 있지만, IF라는 모델이 그 정보를 활용하는 구조가 아닐 가능성이 높다.

**다음 실험**: Exp 4 — max_samples=512, 원본 feature 복원

### 왜 IF를 버리고 OC-SVM으로 바꿨나

이것이 이번 실험의 핵심 결정이므로 근거를 명확히 남긴다.

**IF 클래스에서 시도한 것 전부 소진됨 (Exp 0~4)**:
- Tier 1 (threshold 튜닝): contamination `auto → 0.32 → 0.23`, F1 0.5607 → 0.5812 (+0.0205). 봉우리 확인 후 소진.
- Tier 2 feature: diff 52개 추가(104개), F1 0.5812 → 0.5611 (−0.0201). IF + diff 조합 부적합 확인.
- Tier 2 hyperparameter: max_samples 256→512, F1 0.5812 → 0.5869 (+0.0057). 마지막 의미 있는 개선.

**IF의 구조적 한계 (방법론적 근거)**:

IsolationForest는 데이터를 **수직 또는 수평으로만** 자른다. 예를 들어 "온도 > 85"처럼 하나의 축 기준으로만 경계를 긋는 것이다. 그런데 TEP의 52개 센서는 화학 반응식으로 묶여 있어, "온도가 오를 때 압력도 같이 오른다"처럼 **여러 변수가 동시에 특정 방향으로 움직인다.** 이런 상관관계를 가진 데이터에서 이상(anomaly)은 "두 변수의 관계가 틀어지는 것"으로 나타나는데, IF의 축 정렬 분기는 이것을 포착하지 못한다.

**외부 벤치마크 확인 (Hartung 2023, arXiv:2303.05904)**:

TEP 데이터에 27개 방법을 비교한 연구에서 IF는 **하위권**에 위치한다. 재구성 오차 기반 딥러닝(오토인코더, LSTM-AE)이 상위권을 차지한다. 우리의 F1 ~0.59 천장은 IF의 TEP 구조적 한계와 일치한다. 즉, 더 실험해도 IF로는 이 이상 기대하기 어렵다는 외부 근거가 있다.

**SGDOneClassSVM을 선택한 이유**:

OC-SVM은 **초평면(hyperplane)으로 경계를 긋는다** — 수평/수직이 아니라 임의의 각도. 여러 센서 값의 조합 방향으로 경계를 그을 수 있어, 센서 간 상관관계가 있는 TEP 데이터에 이론적으로 더 적합하다. 또한 `model.py`에 이미 구현되어 있어 코드 변경이 최소화된다. 딥러닝(오토인코더)보다 구현이 단순하고 실패 원인 분석이 쉬워 다음 단계의 비교 기준점으로 적합하다.

---

**변경 사항**: Exp 4와 비교해 두 가지만 변경.
- **모델**: `IsolationForest` → `SGDOneClassSVM(nu=0.23)` — nu는 IF의 contamination과 유사한 역할(임계값 조절), 첫 시도는 Exp 2~4 최적값(0.23)으로 시작
- **전처리**: `StandardScaler` 추가 — OC-SVM은 거리 기반이라 센서 단위(압력/온도/유량 등)에 따라 숫자 크기가 다르면 판단이 왜곡됨. **scaler는 반드시 train 데이터에서만 fit하고 test에는 transform만 적용한다**(data leakage 방지).

1. **threshold 문제 (예상됨)**: nu=0.23이 predicted rate 18.97%로 너무 보수적이다. contamination=0.23이 IF에서 36.13%를 줬던 것과 달리, nu와 predicted rate는 1:1 관계가 아니다. 재현율 0.30은 threshold 문제가 직접 원인.

3. **가능한 원인**: StandardScaler만으로는 TEP 센서 간 강한 비선형 상관관계를 정규화하기에 부족할 수 있다. 또는 SGDOneClassSVM의 선형 커널(기본값)이 이 데이터의 정상/이상 경계를 직선으로 충분히 표현하지 못할 가능성이 있다.

**결론**: 이 결과 하나로 OC-SVM 전체를 포기하기엔 nu 미조정 상태이므로 불공정하다. 그러나 score 품질이 이미 IF보다 낮다는 신호가 있어 큰 기대는 어렵다.

## Exp 8 — Run-level 집계 (IF Exp 4 모델 + 추론 방식 교체)

**날짜**: 2026-07-01

**재현 커밋**: (커밋 후 해시 추가 예정)
`cd src && python run_experiment.py` (EXP_NAME="exp8", RUN_CONTAMINATION=0.322)

**변경 사항**: 모델은 Exp 4와 완전히 동일(IF, contamination=0.23, max_samples=512). 추론 방식만 교체.

- **기존(Exp 0~4)**: 각 row를 독립적으로 판정 → `predict()` → binary label
- **Exp 8**: `decision_function()`으로 각 row의 연속 이상 점수를 뽑고, `simulationRun`별로 평균을 내어 run 전체를 한 번에 정상/이상 판정

**왜 이 방식인가 (t-SNE 인사이트 직접 적용)**:

t-SNE 시각화에서 이상 run의 row들이 호(arc) 모양 궤적을 이루며 정상 군집과 일관되게 분리됐다. 이는 이상 run 안의 개별 row가 하나하나 볼 때는 경계에 있더라도, 같은 run 안에서 **이상 점수가 일관되게 높다**는 의미다. 따라서 run 전체의 평균 점수로 판정하면 개별 row 판정보다 훨씬 안정적으로 이상 run을 구별할 수 있다는 가설이다.

또한 baseline EDA에서 확인된 대로 `simulationRun` 단위로 레이블이 통째로 0 또는 1이기 때문에, run 단위 판정이 문제 구조에 정확히 부합한다.

**로컬 진단 (제출 전)**:
- 예측 positive 비율: **32.16%** (추정 실제 32.20%와 0.04%p 차이 — 역대 가장 정확한 보정)

### 왜 Autoencoder로 전환했나

Exp 12까지 IF + run-level 집계는 F1 0.8870에서 수렴 조짐을 보였다 (Exp 9→11→12: +0.0058, +0.0046 — 개선 폭 감소).

IF의 구조적 한계: 랜덤 수직·수평 분기로 이상을 탐지하므로 센서 간 상관관계(xmeas_12↔xmv_7 완전 상관 등)를 명시적으로 학습하지 않는다. 이상 run은 개별 센서가 정상 범위 내에 있어도 "센서들 사이의 관계가 깨지는 것"으로 나타날 수 있는데, IF는 이 신호를 포착하지 못한다.

Autoencoder는 정상 데이터만으로 학습해 "정상 패턴을 얼마나 잘 복원할 수 있는가"를 직접 학습한다. bottleneck 압축-복원 과정에서 센서 간 상관관계가 자연스럽게 인코딩된다 — 상관이 깨진 이상 run은 복원이 잘 안 되어 재구성 오차(reconstruction error)가 높게 나온다.

외부 벤치마크(Hartung 2023, TEP 비교)에서 재구성 오차 기반 딥러닝이 IF보다 상위권을 차지한다는 근거도 있다.

---

- **학습**: Adam(lr=1e-3), MSE loss, batch=256, 최대 epoch=100, 조기 종료(patience=10), validation 10% holdout.
- **이상 점수**: row별 재구성 오차(MSE) → run별 mean → 상위 RUN_CONTAMINATION 비율을 이상 판정. IF와 방향 반대 — IF는 점수가 낮을수록 이상, AE는 오차가 높을수록 이상.

### 왜 KMeans인가

LOF는 각 점의 로컬 밀도를 주변과 비교해 이상을 탐지한다 → "내 근방이 얼마나 드문가"
KMeans는 정상 데이터를 k개 군집으로 분할하고, 군집 중심까지의 거리를 이상 점수로 사용한다 → "정상 운전 패턴 어디에도 속하지 않는가"
두 접근은 동일한 이상을 다른 관점으로 탐지하므로, 경계 케이스에서 서로 다른 run을 잡을 수 있다. 앙상블 단계에서 다양성을 제공하는 모델이 될 수 있다는 판단.

## Exp 18 — KNN run-level (k 탐색)

**날짜**: 2026-07-03

**재현**: `cd src && python run_knn_grid.py`

### 왜 KNN인가, 왜 run-level 방식인가

LOF/KMeans가 데이터 전체의 밀도 또는 군집 구조를 기반으로 이상을 탐지하는 반면,
KNN은 단순히 "k개 이웃까지의 거리"만 본다 — 글로벌 구조(밀도, 군집)를 가정하지 않는 방법.

**row-level KNN이 아닌 run-level KNN을 선택한 이유 (3가지)**:

1. **계산 문제**: train 250K row × test 711K row KNN은 ball-tree 기준 수십 분 + 메모리 위험.
   run 평균 벡터로 줄이면 (500, 52) × (740, 52)로 즉시 계산 가능.

2. **의미적 일관성**: LOF/KMeans도 row 점수 → run 집계 방식으로 최종 판정함.
   KNN도 같은 레벨(run)에서 비교해야 공정한 비교가 된다.

3. **물리적 타당성**: run 하나의 500 timestep 평균 = 해당 run의 "정상 운전점" 대표 벡터.
   일시 변동보다 구조적 이탈이 이상 탐지의 핵심이므로 평균 벡터가 적절.

구현: 훈련 500개 run 평균 벡터를 학습, 테스트 740개 run 평균 벡터의 k-이웃 평균 거리 계산.
k 탐색: {5, 10, 20, 50} — 훈련 run 500개 대비 1~10% 범위.

### 로컬 실험 결과

| k | separation_idx | train mean | test mean | test min |
|---|---|---|---|---|
| **5** | **137.063** | −0.4420 | −7.8343 | −156.7 |
| 10 | 128.811 | −0.4641 | −7.8566 | −156.8 |
| 20 | 118.234 | −0.4914 | −7.8829 | −156.8 |
| 50 | 102.726 | −0.5384 | −7.9267 | −156.9 |

→ k가 작을수록 분리 지수 높음. k=5 선택.

**이웃 수와 분리 지수 반비례 원인**:
k가 클수록 이웃 범위가 넓어져 정상·이상 run 모두 비슷한 수준의 훈련 run들과 거리를 공유하게 된다.
k=5는 최근접 이웃에만 집중해 이상 run의 고립성을 더 민감하게 포착한다.

**타 모델과의 run 단위 일치도**:

| 기준 모델 | KNN-k5 일치 | KNN만 이상 | 기준만 이상 |
|---|---|---|---|
| LOF-A (Exp15) | **658/740** | 41 | 41 |
| KMeans-Mahal (Exp17) | **660/740** | 40 | 40 |

## Exp 20 — GMM run-level (n_components 탐색)

**날짜**: 2026-07-03

**재현**: `cd src && python run_gmm_grid.py`

### 변경 내용 및 근거

KMeans-Mahal k=100 실험에서 Global Σ⁻¹ + k 증가 방향의 천장 확인 (이진 예측 불변).
GMM으로 전환해 두 가지 한계를 동시에 극복:
1. 하드 할당 → 소프트 할당 (EM 기반)
2. Global Σ⁻¹ → Per-component Σ_k (운전 구간별 상관 구조 개별 학습)

**row-level이 아닌 run-level 벡터로 학습한 이유**:
row-level(250K행) full covariance GMM은 EM 반복당 52×52 행렬 k개 추정으로 계산 비용이
수십 분 이상 소요됨 (실측). run 평균 벡터(500×52)로 전환 시 수 초 내 완료, 수치 안정성도 확보
(500/k ≥ 25행/성분).

### 로컬 결과

| k | LOF-A 일치 | Mahal 일치 | GMM-only run |
|---|---|---|---|
| 5 | **686/740** | **688/740** | 26~27 |
| 10 | 682/740 | 684/740 | 28~29 |
| 20 | 672/740 | 670/740 | 34~35 |

**주의**: separation index (수십만 단위)는 log-likelihood 스케일로, Mahalanobis 거리 스케일과
직접 비교 불가. 실질 판단 기준은 LOF/Mahal 일치도.

**k=5 선택 이유 (스크립트 자동 선택 k=20 대신)**:
- k=20은 GMM-only 35 run으로 검증된 모델 대비 불일치가 너무 큼
- k=5가 LOF/Mahal과 가장 가까운 합의 형성 (686~688/740)
- 고유 플래그 26개로 리스크 최소화

**제출 파일**: `output_exp20(GMM).csv` (k=5)

**점수 (public)**: F1 **0.9367**, Accuracy **0.9595** — **전체 실험 신규 최고점**

**Confusion matrix 역산** (PP=227,520, N=710,400):
- error = 28,772 → TP≈212,934, FP≈14,586, FN≈14,186, TN≈468,694
- Precision≈0.9359, Recall≈0.9376

**전체 모델 비교**:

| 모델 | Precision | Recall | F1 | FP 행 | FN 행 |
|---|---|---|---|---|---|
| AE (Exp13) | 0.9289 | 0.9122 | 0.9205 | 16,182 | 20,337 |
| LOF (Exp15) | 0.9182 | 0.9292 | 0.9237 | 18,616 | 15,909 |
| KMeans-Mahal (Exp17) | 0.9195 | 0.9361 | 0.9277 | 18,323 | 14,284 |
| **GMM k=5 (Exp20)** | **0.9359** | **0.9376** | **0.9367** | **14,586** | **14,186** |

**왜 GMM k=5가 KMeans-Mahal을 이겼나**:

KMeans-Mahal의 Global Σ⁻¹은 500개 훈련 run 전체의 상관 구조를 단일 행렬로 평균낸다.
GMM k=5는 성분마다 고유한 Σ_k를 추정하므로 TEP의 서로 다른 운전 조건 구간이 각자의
상관 구조를 따로 학습한다. Mahal이 오탐했던 ~4개 run(전체 공분산 기준 이상처럼 보이나
해당 운전 구간 기준으로는 정상)을 GMM이 올바르게 정상으로 판정 → FP 3,737행 감소.

**⚠️ 과적합 우려 (최종 평가 리스크)**:

구조적 문제:
- 성분당 파라미터 수: 평균(52) + 공분산(52×53/2) = **1,430개**
- 성분당 학습 데이터: 500 run / 5 = **약 100개**
- 파라미터 수(1,430) >> 데이터 수(100) → 구조적 과적합 위험

실제로 작동한 이유: TEP 피처가 강한 상관으로 유효 차원이 52보다 낮고, 정상 run이 매우 좁은
클러스터를 형성해 공분산이 사실상 저차원 구조. 그러나 이는 중간 평가 테스트 분포에 맞춰진
것일 수 있어 최종 평가에서 정상 run 분포가 조금만 달라도 FP 급증 가능.

완화 방법:
1. `reg_covar` 증가(1e-6→1e-2)로 공분산 정규화 강화
2. `covariance_type='tied'`로 파라미터 수 대폭 감소
3. 현재 점수가 과적합 산물인지 최종 평가와 비교로만 검증 가능

**다음 우선순위**: reg_covar 튜닝으로 과적합 완화 실험 → AE 개선 (bottleneck 16)

## Exp 22 — PCA-SPE run-level (k=30, 설명분산 88.8%)

**날짜**: 2026-07-06

**재현**: `cd src && python run_pca_grid.py`

### 변경 내용 및 근거

GMM(Exp 20~21) 이후 미탐색 통계/거리 기반 방법 점검 시 PCA 기반 MSPC 누락 확인.
TEP 이상 탐지 논문(Chiang 2001, Lee 2004)에서 표준 벤치마크로 사용되는 방법이어서 비교 필요.

**SPE(Squared Prediction Error) 선택 이유**:
- SPE = ||x - PCA재구성(x)||²: 정상 부분공간 밖으로의 이탈 거리
- 이상 발생 시 센서 간 상관 구조 붕괴 → SPE 즉각 반응
- EDA에서 확인한 r≈1.0 상관 구조가 탐지 신호로 직접 작용 (GMM과 같은 메커니즘)
- T²는 부분공간 내 극단값 탐지 → 상관 붕괴 감지에 SPE가 더 직접적

**k=30 선택 이유**:
- k가 작으면(5, 37.5%) SPE에 정상 변동도 포함 → 잡음 증가
- k=30(88.8%) SPE는 주요 정상 축을 제거한 잔차만 담아 분리력 최대
- GMM(현재 최고 모델)과 일치도 694/740으로 모든 k 중 최고

### 로컬 결과

| k | 설명분산 | SPE run sep | LOF 일치 | Mahal 일치 | GMM 일치 |
|---|---|---|---|---|---|
| 5  | 0.375 | 1,042 | 694/740 | 722/740 | 690/740 |
| 10 | 0.527 | 1,355 | 694/740 | 714/740 | 694/740 |
| 15 | 0.627 | 1,556 | 694/740 | 722/740 | 690/740 |
| 20 | 0.720 | 1,903 | 694/740 | 712/740 | 692/740 |
| **30** | **0.888** | **2,413** | **694/740** | **706/740** | **694/740** |

SPE는 모든 k에서 LOF 일치도가 694/740으로 고정 → 안정적 예측 패턴.
k=30이 Mahal보다 GMM에 가까운 것은 긍정적: GMM(0.9372)이 Mahal(0.9277)보다 높고,
SPE가 같은 방향에 위치.

**제출 파일**: `output_exp22(PCA-SPE).csv` (k=30)

**점수 (public)**: F1 **0.9167**, Accuracy **0.9459**

**전체 모델 비교 업데이트**:

| 모델 | F1 | Accuracy |
|---|---|---|
| GMM tied (Exp21) | **0.9372** | 0.9595 |
| GMM full (Exp20) | 0.9367 | 0.9595 |
| KMeans-Mahal (Exp17) | 0.9277 | 0.9541 |
| LOF (Exp15) | 0.9237 | 0.9514 |
| AE (Exp13) | 0.9205 | — |
| **PCA-SPE k=30 (Exp22)** | **0.9167** | **0.9459** |

**분석 — 왜 GMM보다 낮게 나왔나**:

PCA는 row-level(250K 훈련 행)로 학습하고, row 단위 SPE를 run 평균으로 집계하는 구조다.
GMM은 run 평균 벡터(500×52)로 직접 학습한다.

핵심 구조 차이:
- **PCA**: "개별 타임스텝의 재구성 오차를 run 전체에서 평균" → 정상/이상 타임스텝이 섞여 신호가 희석
- **GMM**: "run 평균 벡터 자체가 정상 분포에서 벗어나는가" → run-level 이상을 직접 모델링

TEP 테스트 데이터는 이상 run이라도 초반 타임스텝은 정상으로 시작하는 경우가 있다.
PCA-SPE는 이 정상 타임스텝의 낮은 SPE가 평균을 끌어내려 이상 run의 신호를 약화시킨다.
GMM은 run 전체 평균 벡터를 보므로, 이상이 충분히 진행된 run은 평균 자체가 이탈해서 탐지된다.

sep 지수(PCA: 2,413 vs GMM: 600,000)는 "학습 데이터 단위"가 달라 직접 비교 불가 —
PCA sep은 행 단위 재구성 오차 기준이고, GMM sep은 로그우도 기준이다.

**결론**: PCA-SPE는 화학공정 모니터링 이론상 적합하지만, run-level 예측 문제에서는
run 벡터를 직접 모델링하는 GMM이 구조적으로 더 잘 맞는다.

설계 근거 및 기대 효과는 ENGINEERING_LOG 5-4 섹션에 사전 기록됨.

### 로컬 그리드 탐색 결과 (nu × gamma)

| nu | gamma | sep | LOF 일치 | Mahal 일치 | GMM 일치 |
|---|---|---|---|---|---|
| 0.05 | scale | 1.179 | 660/740 | 662/740 | 680/740 |
| **0.05** | **auto** | **27.481** | **650/740** | **656/740** | **664/740** |
| 0.05 | 0.1 | 7.395 | 652/740 | 658/740 | 664/740 |

| 0.1 | auto | 27.295 | 652/740 | 658/740 | 666/740 |

| 0.3 | auto | 27.086 | 650/740 | 656/740 | 666/740 |

**gamma='scale' sep이 낮은 이유**:
scaler가 250K 행에서 fit되었으므로 run 평균 벡터(500개)는 분산이 크게 줄어든 상태.
`gamma='scale' = 1/(n_features × X.var())`에서 run 벡터의 X.var()가 약 1/500 수준이므로
실효 gamma가 52 × 500 = ~9.6 수준으로 급등. 매우 좁은 RBF 경계 → sep 낮음.
`gamma='auto' = 1/52 ≈ 0.019`는 이 문제 없이 더 부드러운 경계를 만듦.

**전체적으로 우려스러운 패턴**:
모든 설정에서 LOF 일치 650~662/740, GMM 일치 664~680/740.
GMM 자체의 LOF 일치도가 694/740임을 감안하면 OC-SVM은 검증된 모델들보다
훨씬 많은 run(38~45개)에서 예측이 다름 → 높은 실제 오류율 시사.

**제출 파일**: `output_exp23(OC-SVM).csv` (nu=0.05, gamma='auto')

**사전 예측 (기록용)**:
- LOF 일치 650/740(45 run 차이) 기준: LOF가 0.9237이었고 OC-SVM은 더 많이 다름
- GMM 일치 664/740(38 run 차이) 기준: 현저히 낮은 일치도
- 예상 F1 범위: **0.87~0.92** (기대치 낮음, 비관적 시나리오에 가까움)

**점수 (public)**: F1 **0.7866**, Accuracy **0.8622**

**사전 예측 대비**: 예측 범위 0.87~0.92, 실제 0.7866 — 예측보다 더 낮음 (비관적 시나리오 하회)

**분석 — 왜 예측보다 더 나빴나**

로컬 지표(LOF 650/740, GMM 664/740 일치도)만으로는 실제 F1이 이 정도까지 낮을 것을 예측하지 못했다.
근본 원인은 OC-SVM 알고리즘 자체의 구조적 문제였다:

**① 단일 경계 vs 다봉 분포**
TEP 정상 run은 여러 운전 구간(regime)에서 각각 다른 분포를 형성한다.
GMM은 k=5개 성분으로 각 regime의 밀도를 개별 추정한다.
OC-SVM은 단일 초평면(hyperplane)으로 전체 정상 영역을 하나로 감싸려 한다.
다봉 분포를 단일 경계로 감싸면 regime 사이 공백 공간도 "정상"으로 포함되고,
테스트 이상 run이 그 공간에 들어오면 탐지하지 못한다.

**② 점수 품질: signed distance vs log-likelihood**
GMM의 score_samples = log p(x): 전체 정상 분포에서 얼마나 가능성이 낮은지 측정.
OC-SVM의 decision_function = 초평면까지의 부호 거리: 단일 경계와의 거리.
다봉 구조에서 초평면 거리는 실제 이상도와 상관이 약하다.

**③ nu vs RUN_CONTAMINATION 불일치**
nu=0.05: 훈련 데이터 5%(25개 run)가 경계 밖에 있어도 허용.
RUN_CONTAMINATION=0.32: 테스트 run의 32%를 이상으로 판정.
훈련 오탐율 5%로 학습한 경계에 테스트 32% 기준을 적용하는 구조적 불일치.

**결론**: hyperparameter 튜닝으로 해결할 수 있는 문제가 아니라
알고리즘과 데이터 구조 사이의 근본적 불일치.

**다음 우선순위**: OC-SVM 추가 실험 포기, GMM+Mahal 앙상블 검토
